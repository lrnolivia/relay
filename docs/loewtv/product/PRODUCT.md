# Arc TV appliance experience

Arc is Lauren's minimal Home screen on the TCL 55QM751G / G08, Android 14 V321. This isolated source extends the preserved 4124 appliance build; it is not an upstream repository or a public release.

The user has approved Arc-owned input and Settings screens. Home retains its existing clock, greetings, input tiles and animated accents. Regular text uses the TV’s Roboto system family; Momo Trust Display remains the decorative headline family. Selecting an input opens full-screen video through the same native TvView session. Input screens have no bottom buttons. No-signal output becomes pure black after its transient header hides. Info shows the source overlay without leaving playback; Input opens the Arc picker and Settings opens the Arc hub. Home and Back retain a reliable return path.

Settings stays on one screen with two visible category rows and a rounded section surface directly beneath its parent row. The TV row contains Picture, Sound, Network, Remotes, Accessibility, Inputs, Apps and System; selecting a TV category places its section between the TV and Arc rows. The Arc row contains Home (live preview and dimming), Appearance, Screensaver, Quick menu and All TV settings; selecting an Arc category places its section below the Arc row. Focusing a category replaces the attached section, and Select enters its controls. Picture mode and other choice controls expand compact, indented radio options below their own parent row, with one choice list open at a time. Brightness and other ranges reveal a horizontal slider beneath the focused row. Up/Down navigates controls and Left/Right adjusts a focused slider. Back collapses an expanded choice list and restores its parent, then returns to the selected category, then closes Settings. Up from the first control also returns to the selected category.

Supported picture controls show confirmed TV values; availability follows the current input, preset and native support. Unavailable input mapping or control dependencies keep unsupported adjustments unavailable. Protected sound, network, pairing, accessibility and system actions open their specific retained TV pages. Arc-launched native TCL picture, sound and Quick panels request a return to Arc when closed, without opening the stock Settings root. Direct Google TV leaf pages retain their existing routes, and All TV settings remains the intentional escape hatch to the full native Settings app. Android-exposed device status is read-only, and Current audio output describes the route rather than Dolby/Atmos codec detection. The Settings title, section labels, glyphs and rows retain the TV’s native Google TV Settings anatomy: a 37-point Roboto Settings title, 16-point attached section titles, uppercase group labels, glyphs in 40-point circles, 15.5-point rows with 13-point secondary text, and a white rounded focus pill with dark text. Arc’s Gray depth surfaces and the current source’s accent continue on controls and focused glyph plates. Glyphs remain Google’s filled Material glyphs. Category panels crossfade in 160 milliseconds and nested options expand in 180 milliseconds; reduced motion skips these entrances. The requested Input, Settings and hamburger short-press shortcuts route to Arc through TCL’s reversible shortcut configuration. The hamburger hold gesture retains its stock repeat handling and does not open Arc on release.

Home previews are muted. Full input playback uses normal session volume. Session reset restores normal gain before release. Preview tuning continues to suppress vendor CEC takeover. Arc writes supported picture controls only in response to an explicit user adjustment, using current-input scope where the native API provides it, and confirms the result from TV readback. It never automatically changes picture or audio globals, and it does not change global CEC, firmware, boot state, DRM, calibration or networking settings.

The Arc input picker is a full-bleed horizontal bottom sheet whose cards are Home’s input tiles at Home’s own scale (490 × 300 design units, 122.5 × 75 logical at 960 × 540): 72-unit glyph, 44-unit medium name, 26-unit port and connection line, and Home’s focus ring, breathing glow, crossing shine and 30 × 204 source bar. The row starts at Home’s grid margin so sheet cards line up under Home’s cards, with Home’s 86-unit gaps. Only the sheet backdrop has a gradient: black rises along a smootherstep curve over 62% of its height, so the fade has no visible start line. Horizontal remote focus scrolls every source into view; selecting a source switches Arc’s existing playback route and keeps its single decoder alive. Non-selected sources dim while one is playing. The device’s own shortcut configuration routes Input and Settings to explicit Arc intents with a saved inverse; no unrelated remote mapping is changed.

The shared PC tower glyph has a tight canvas instead of an oversized empty right margin. Source accent bars glow and share the border’s single diagonal shine pass on focused Home and picker buttons, and on the input header’s accent bar. The active-video header keeps a static neutral outer frame and a thin bright inner stroke, with no colored outer stroke or frame shine; the card clips its source bar’s tighter bloom so no color reaches any edge. They have no independent bar shine. Source colors are randomized once per cold Arc/Dart launch and remain consistent across Home, input playback and sheets, including app resume. Reduced motion retains the colored bar and static glow while suppressing the moving shine.

Picker focus matches Home exactly: the colored ring sits 21 design units outside the card, and the card keeps its own neutral border inside, so the gap between them equals Home’s. The picker has no X control; the remote’s Back action dismisses it.

The visual world is inherited from `lib/widgets/appliance_home.dart`: black surfaces, neutral gray text, Roboto utility text, existing Momo Trust Display greetings and the existing teal/sienna/amber/green/coral accents. Arc input routing is an optional, initially disabled Accessibility service. It observes only TCL TV activity window changes, reads the active HDMI port through TCL's read-only API, and recreates Arc's navigation task directly into playback of that port. It requests no screen-content access and no key or gesture control. The user must enable it in native Settings; no shell permission grants are used. It does not suppress SystemUI's HDR/Dolby Vision logo.

Input signal loss uses an opaque native black backing above TvView and below Flutter. The backing covers Connecting, No signal, blocked and unavailable states while retaining the input session; a real available-video callback removes it so playback recovers. Arc's window also has a black backing instead of revealing the paused TCL activity.
