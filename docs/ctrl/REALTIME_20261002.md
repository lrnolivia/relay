# ctrl event transport

The proposed transport is a same-origin authenticated WebSocket backed by one hibernating Relay Durable Object. It stores at most250 invalidation envelopes for24hours, not source/evidence/user data. IDs are monotonic, repeated publish operation IDs deduplicate, and missing/expired/future cursors demand canonical snapshot resync. Browser connections reauthenticate at most every5minutes and sooner when the validated Access JWT expires. Origin and the existing gateway authorization remain required.

Successful allowlisted MCP mutations, operator writes and existing authenticated CI evidence ingest/run writes invalidate subscribers. Publishing is bounded to2seconds after canonical writes. No mutation body is broadcast. Source requests outside Relay (for example a direct GitHub push) are not automatically observed by this channel; the UI keeps a periodic snapshot fallback and must not advertise those outside events as instant. Event delivery is best effort after the canonical write, with reconnect/snapshot recovery, not an atomic transaction with GitHub or an exactly-once claim. Failure to notify never changes a successfully committed write into a retryable mutation error.

Activation is intentionally separate. The source exports RelayEvents but does not change wrangler bindings/migrations or security configuration. The reviewed activation must add a RELAY_EVENTS binding for classRelayEvents and a SQLite migration, then verify a real authenticated WebSocket, replay and expiry. ctrl's separate Worker needs the approved Relay service binding and protected ctrl.loew.fi Access coverage; keep the same audience and approved users. No new API token is needed in browser code. Keep existing Relay website/MCP as rollback.
