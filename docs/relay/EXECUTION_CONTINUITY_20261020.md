# Execution continuity

The finite coordinator in `scripts/relay-continuity.mjs` owns acceptance advancement. Executor configuration may include `continuity`; both the normal `runExecution` entry point (including dispatch) and the explicit `relay-executor.mjs continue` command use it. Existing single-job configurations remain truthful process receipts with `objective_completed:false`; no queue is invented from unstructured prose. Runner sync remains a model-free observation service, not an authority to restart held assignments.

A plan declares schema1, explicit authorization, `objective_digest` (SHA256 of JSON `{goal,acceptance}` matching the current canonical assignment), unique `criteria`, environment identity and ordered stages. Every stage declares `id`, kind (`implementation`, `test`, `review`, `ship`, `runtime`), covered criteria, `depends_on`, complete source/config `inputs`, a bounded trusted `verify` argv and bounded worker `prompt`. Every criterion must be covered. Optional trusted `command` argv performs coordinator-owned actions such as the registered source/release workflow; verifiers must only inspect. Commands inherit existing host permissions, never shell interpolation or new credentials. Source-protected coding jobs retain their admitted Git baseline; publication commands run after checkpoint accounting. No command exit alone completes acceptance: its verifier must pass afterward. Review/shipping/runtime verifiers always read current external state. Required canonical CI and deployment readback remain exact-revision gates.

The private journal outside the checkout persists complete plan identity, stage states, dependency/input/environment digests, job/action intent, attempt count, process receipt and separate verification evidence. Interrupted actions reconcile by original identity. Queued, independently confirmed submissions can start once; running/unknown jobs never relaunch. Unknown command outcomes require successful verifier readback before advancement. A stale lock requires process reconciliation. No journal is deleted to work around uncertainty.

Implementation/test receipts reuse only unchanged declared relevant source, verifier, environment, objective and dependency receipts. The adapter measures the actual Node/platform/architecture, relevant process environment, source toolchain files and installed lock receipt on each input check. Removed files invalidate input evidence. Changed later-stage inputs revalidate earlier stages before completion. Old source SHA provenance is retained; scoped content reuse never claims that old CI tested a new commit. Identical failure fingerprints permit two attempts, after which only that stage and dependencies park. Reproducible test/build failures block promotion and retain authorized diagnosis/repair. Plan/environment changes require explicit checkpoint reconciliation.

Safety control preserves existing `held` semantics for intentional/user/global/security stops and production recovery. Scoped `wait`/`recover_wait` operations use exact control/block revisions and a two-attempt budget; recovery cannot clear a project/global stop. Candidate `quarantine` records exact source identity, leaving unrelated work admitted. The public publication probe checks the actual Workers CI source; raw version publication under quarantine requires a retained healthy/approved target, otherwise it uses the canonical source-guarded route. Quarantine does not silently expire. Existing project holds are never inferred to be transient and cleared automatically.

Night Shift parks local holds/oversight failures. Unknown launches reserve their job and shared host/checkout; independent hosts continue. Restart never replays an existing launch receipt. Global/operator stops and unavailable global authority stop the whole pass.
