# Relay web and in-chat interface

Relay has one interface source in `apps/web/public/`, built into both the web asset map and the MCP Apps HTML resource by `apps/web/build.mjs`. The imported operator and full-screen human QA components were moved here from Runner; the unused older dashboard implementations were removed. `packages/shared-ui/tokens.css` implements Terra Prime HUI foundations from Figma file `6hjtD0UcLwU44DPDDrAKht`, foundation node `4:4`: warm dark/light surfaces, Inter interface typography, Momo brand accent, deliberate orient/action/resolve colors, generous spacing, and accessible control targets. Illustrations are excluded by the user's instruction.

Today surfaces attention, active work and automation. Projects shows canonical registrations and claims. Review retains the existing exact-evidence questions, answers, notes, verdict and live/captured preview. Night Shift is a feature view over the same worker configurations and run state; it adds no scheduler or storage.

`apps/mcp/index.js` routes web and native MCP through the same deployed Worker. Existing SOURCE/CLOUD/VERIFY and OAuth remain in Inspector; Runner's internal API supplies worker and QA functions. Web API requests first pass the native gateway's cryptographic identity verification, then the existing Access guard. Cross-origin web writes are blocked. MCP's app-only `relay_ui_request` is a bounded adapter to these same APIs and is dispatched only after the native MCP authentication probe. Trust travels as an internal parameter, not a caller-supplied identity header. It accepts only supported project/worker/Visuals routes, GET/POST methods, bounded bodies and known filters. It introduces no arbitrary URL proxy or second review store.

Projects read Relay's authenticated source adapter and exclude compatibility aliases. Both native MCP worker tools and web controls call the same internal Runner implementation and use the existing Relay GitHub App installation. Existing legacy Runner token support remains for rollback. Human review writes retain the existing R2 evidence key and evidence identity. In-chat images use the same evidence route; oversized full-resolution captures direct the user to web review.

Workspace validation: `npm test` includes Inspector, Runner, provenance/layout/contracts and web API tests. `npm run build` regenerates the committed self-contained asset module and checks workspace entrypoints. CI checks generated output for drift. Browser validation exercises navigation/deep links, error states, light/dark/mobile layouts and review saving through both HTTP and the MCP host bridge. Core operator flows do not require model inference.
